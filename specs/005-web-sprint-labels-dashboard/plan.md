# Implementation Plan: Web Sprint Labels Dashboard

**Branch**: `005-web-sprint-labels-dashboard` | **Date**: 2026-06-05 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/005-web-sprint-labels-dashboard/spec.md`

## Summary

Build a browser-based dashboard served by a new `cmd/web-sprint-labels-report` Go binary. The dashboard shows sprint issues per team with label-toggle buttons that write back to Jira. The backend exposes a small REST API (5 endpoints) over `net/http`; the frontend is a vanilla JS/CSS/HTML SPA embedded in the binary via `//go:embed`, requiring no build step.

## Technical Context

**Language/Version**: Go 1.24.0 (existing project requirement)

**Primary Dependencies**:
- `github.com/andygrunwald/go-jira v1.17.0` — existing; used for sprint listing and issue label updates
- `github.com/joho/godotenv v1.5.1` — existing; `.env` loading
- Go standard library `net/http`, `embed`, `encoding/json` — no new external dependencies

**Storage**: None (stateless; Jira is the source of truth for labels)

**Testing**: `go test ./...` (existing project tooling)

**Target Platform**: macOS / Linux server (darwin + linux amd64); launched as a local CLI binary

**Project Type**: Web service (HTTP server binary) + embedded SPA

**Performance Goals**: Issue table for any sprint loads within 3 seconds; label toggle responds within 2 seconds (SC-001, SC-002)

**Constraints**: No external npm/node build step; no new Go module dependencies beyond existing; binary must start via `./bin/web-sprint-labels-report -port 8080`

**Scale/Scope**: Internal tool; 1–5 concurrent users; up to ~200 issues per sprint

## Phase 0: Research — COMPLETE

All decisions are documented in `research.md`. Key resolved questions:

1. **Sprint retrieval**: Paginate `GetAllSprintsWithOptions(boardID, &{State:"active,closed"})`, sort by ID desc, take first 5. (Decision 2)
2. **Label update**: Use `client.Issue.UpdateIssue(key, {"update": {"labels": [{"add"|"remove": label}]}})`. (Decision 3)
3. **Frontend delivery**: `//go:embed web` in `internal/dashboard/handler.go`; vanilla JS/CSS/HTML; no build step. (Decision 1)
4. **Routing**: Go 1.22+ `net/http` pattern matching — no external router. (Decision 5)
5. **Theme persistence**: `localStorage` key `sprint-dashboard-theme`; set on `<html>` before render. (Decision 6)
6. **Package**: New `internal/dashboard`; leave `internal/server` unchanged. (Decision 7)
7. **Issue type icons**: 5 + 1 fallback SVG files embedded in `web/icons/`. (Decision 4)

## Phase 1: Design & Contracts — COMPLETE

### New Jira Service Methods

#### `GetSprintsForBoard(boardName string, limit int) ([]jira.Sprint, error)`

```
1. Call GetBoard(boardName) → board.ID
2. Paginate GetAllSprintsWithOptions(board.ID, {State:"active,closed", StartAt:0, MaxResults:50})
   until SprintsList.IsLast == true
3. Collect all sprints, sort by ID descending
4. Return first `limit` sprints (or all if fewer than limit)
```

#### `UpdateIssueLabel(issueKey, label string, add bool) error`

```
op := "add" if add, else "remove"
Call client.Issue.UpdateIssue(issueKey, {
  "update": {"labels": [{op: label}]}
})
Return error if non-2xx response
```

### Dashboard Handler Routes (Go 1.22+ pattern matching)

```
mux := http.NewServeMux()
mux.Handle("GET /static/",       http.StripPrefix("/static/", http.FileServerFS(webFS)))
mux.HandleFunc("GET /",          h.serveIndex)
mux.HandleFunc("GET /api/teams", h.getTeams)
mux.HandleFunc("GET /api/teams/{component}/sprints", h.getSprints)
mux.HandleFunc("GET /api/sprints/{sprintID}/issues", h.getSprintIssues)
mux.HandleFunc("POST /api/issues/{issueKey}/labels", h.updateLabel)
```

### Frontend Architecture

```
index.html
  ├── <link> style.css
  ├── <script> theme-init (inline, sets data-theme before paint)
  └── <script src="app.js" defer>

style.css
  :root { --bg: #fff; --text: #1a1a1a; ... }
  [data-theme="dark"] { --bg: #1e1e2e; --text: #cdd6f4; ... }

app.js  (module, no bundler)
  State:  { selectedTeam, selectedSprint, issues, configuredLabels }
  on load: fetchTeams() → renderTeamButtons() → auto-select first → fetchSprints()
  on team click: fetchSprints() → renderSprintButtons() → clear issue table
  on sprint click: fetchIssues() → renderTable()
  on label click: optimistic state flip → callUpdateLabel() → revert on error
  on theme toggle: toggle data-theme on <html> → persist to localStorage
```

## Implementation Notes

### `cmd/web-sprint-labels-report/main.go` Skeleton

```go
func main() {
    port := flag.Int("port", 8080, "HTTP listen port")
    debug := flag.Bool("debug", false, "verbose logging")
    flag.Parse()

    cfg, err := config.Load()
    // ... error handling ...

    jiraSvc, err := jiraservice.NewJiraService(...)
    // ... error handling ...

    handler := dashboard.NewHandler(cfg, jiraSvc)
    addr := fmt.Sprintf(":%d", *port)
    log.Printf("Starting dashboard on http://localhost%s", addr)
    log.Fatal(http.ListenAndServe(addr, handler.Routes()))
}
```

### `.env` — No New Variables Required

All required configuration is already present:
- `JIRA_URL`, `JIRA_USERNAME`, `JIRA_API_TOKEN`, `JIRA_PROJECT_KEY` — Jira connection
- `TEAMS` — team/board config
- `REPORT_LABELS` — label button set
- `JIRA_EPIC_FIELD`, `JIRA_SP_FIELD` — custom field IDs

### Error Handling Contract

- Jira API errors → `502 Bad Gateway` with `{"error": "..."}` (never panic)
- Invalid path params → `400 Bad Request`
- Label not in configured list → `400 Bad Request` (validated before Jira call)
- Empty sprint → `200 OK` with `{"configuredLabels": [...], "issues": []}`
- Component not in config → `404 Not Found`
